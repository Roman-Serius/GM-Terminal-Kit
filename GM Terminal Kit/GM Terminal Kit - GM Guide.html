GM Guide

Reference for building and running scenarios in GM Terminal Kit.

1. Getting started

GM Terminal Kit is a single HTML file. It runs in a web browser (Chrome, Safari or Firefox) and needs no installation or account.

The kit has two modes:

  • GM workspace: where the scenario is built. It is laid out like a file manager, with folders on the left, files in the middle and a toolbar along the top.
  • Player mode: a full-screen retro terminal for the players, who explore it by typing commands such as DIR and TYPE.

Sample scenario

On a blank drive, click Load the sample scenario, or open Settings and click Load sample. The sample, Kestrel Station, is a short game that shows off the kit. Start Player mode and type TYPE README. Each step of the puzzle uses a different feature, and a line starting with [KIT] explains which one: hidden files, a login that delivers mail, a password-protected folder, a self-destructing file only one account can open, a program that asks a question, a countdown with sound and a red alert theme, FIND, a secret phrase and two endings. A timer event gives a hint after four minutes. The full solution is in the hidden file SOLUTION.TXT.

The sample also has feature reels, commands that demonstrate one thing each:

CommandShows
SOUNDSEvery sound effect, one by one
VOICEThe @speak voice
EFFECTSFlash, shake and glitch, then all at once
THEMESEvery theme; press Enter for the next one
ASKA question with branching answers
GIFAn animated GIF playing as ASCII art
ALLEverything above in a row

Afterwards, open the GM workspace and look at Events, Event map and Answer key to see how it was built. The examples in this guide, such as OVERRIDE.EXE and SHUTDOWN 4471, come from the sample.

2. Files and folders

The drive is always C:\. All files and folders sit inside it.

Creating files and folders

Right-click an empty part of the file area (long-press on a touch screen) to open a menu with these options:

  • New Folder
  • New Text File: notes, memos, logs and letters. Players read them with TYPE.
  • New Program (.EXE): a script that plays out when run. See Programs and commands.
  • Import Files…: adds files from the computer.

New text files and programs open in the editor immediately. Double-click a file to edit it later.

Importing files

Drag files onto the window or onto a folder, or use Import Files….

  • Images (JPG, PNG, GIF and similar) become picture files, shown to players as ASCII art. They are scaled down to 800 pixels wide on import.
  • Animated GIFs are converted to ASCII-art frames on import, and play as animations in the terminal. Double-click one to preview it. Very long GIFs keep every second or third frame (at most 120), so the scenario stays small enough to save.
  • .txt, .md, .nfo, .log and .asc files become text files.
  • .bat and .scr files become programs.

Imported file names are converted to capital letters.

Organizing

  • Open a folder by double-clicking it, or by clicking it in the sidebar or the path bar.
  • Move an item by dragging it onto a folder in the file area, sidebar or path bar, or with right-click → Move to….
  • The right-click menu also has Rename…, Duplicate and Delete. Duplicating a folder copies its contents.
  • Names must be unique within a folder. A repeated name gets a number added, e.g. NOTE 2.TXT.

Badges

Symbols under each file show its settings:

BadgeMeaning
PadlockPassword protected.
PersonRestricted to one account.
Lightning bolt and event nameAppears when that event fires. Gray while waiting, green once fired.
FlameSelf-destructs after it is read or run.
"GIF" tagAn animated GIF, which plays as ASCII animation.
Eye with a line through itHidden from a normal DIR listing. The file also appears faded.
"Revealed" tagA program revealed it during play.
"Destroyed" tag, name crossed outIt self-destructed or was deleted during play. Players can't see it; the GM workspace still shows it.

3. Get Info: locks and secrets

Right-click a file or folder and choose Get Info… to set its access rules.

Password (asked when opened)
Players must enter it before reading, running or opening the item. Capitalization is ignored, so falcon works for FALCON. A correct password keeps the item unlocked for the rest of the session. A password on a folder protects everything inside it.
Only this user can open it
Any other account gets Access denied, even with the correct password. Players must LOGIN as that account first.
Appears when
"Always there", or one of the scenario's events. Until the event fires, the item is invisible to players: DIR does not list it, and opening it by name returns "File not found". See Events.
Hidden from DIR
DIR leaves it out, but DIR /A lists it, and it can still be opened by name.
Self-destructs after it is read or run
Files and programs only. After one read or run, players see *** FILE SELF-DESTRUCTED *** and the file disappears for them. The GM workspace keeps it, marked Destroyed, and Reset session restores it.

These settings can be combined. For example, a file can be password protected, restricted to DKANE, set to appear with the "Lockdown" event, and set to self-destruct after reading.

4. Accounts and mail

Click Accounts to manage logins.

  • The first account is the guest account. It cannot be deleted, and LOGOUT returns to it. It normally has no password, so players can start without one.
  • + Account adds a login. A blank password means no password.
  • Account passwords ignore capitalization.

Mail

Each account has an inbox. + Mail adds a message with a sender, subject and body. Players read mail with MAIL while logged in as that account.

The "Arrives when" menu on each message works like "Appears when" on files: a message set to an event arrives when that event fires. An event announcement can tell players the message has arrived (see Recipes).

Renaming an account breaks files restricted to the old name. Nobody can open them until their Get Info is updated. The Answer key lists every restricted file.

5. Events

Events change the game while it is played. When an event fires, files and mail attached to it appear, and its script runs: a message, a character speaking, or a whole finale. Events can be fired by the players' own actions, so a scenario can run with no GM at all.

Creating an event

  1. Click Events, then + Event, and give it a name, e.g. Power restored.
  2. Optional: write what happens in "When it fires, run". This is a script in the same format as a program (see Programs and commands). A single line such as *** 1 NEW MESSAGE *** is enough for a simple announcement.
  3. Optional: add conditions under "Fires when any of these happens" (see below).
  4. Optional: tick events under "Only after these have fired".
  5. Optional: choose an event in the "Also fires" menu, or set "Fires by itself after" a number of minutes.

Files are attached to an event with "Appears when" in Get Info, and mail with "Arrives when". Under each event, the Events window lists what it unlocks.

Conditions

+ Condition adds a player action that fires the event. Any one of an event's conditions is enough.

ConditionFires when a player…
Logs in aslogs in to that account with LOGIN.
Typestypes that exact phrase, e.g. DIAL 0714. Capitals and extra spaces are ignored.
Reads filereads that file with TYPE (pictures included).
Runs programruns that program, after its script has finished.
Reads mailopens that message with MAIL.
Unlocksenters the correct password for that file or folder.
Enters foldermoves into that folder with CD.

A typed phrase works as a secret command. It never gets "Bad command or file name", and it takes priority over a custom command with the same name. That makes code entry possible: a custom command SHUTDOWN can answer every wrong code, while an event with the condition "Types SHUTDOWN 4471" handles the right one. Once an event has fired, its phrase stops working.

Only after

An event with "Only after" ticks waits until those events have fired. Until then its conditions, @trigger lines and timer have no effect, so steps happen in the intended order. For example, typing YES does nothing until a certain file has been read. GM hotkeys and the Fired checkbox ignore this rule.

Other ways to fire an event

MethodNotes
@trigger in a script A line such as @trigger Vault opened in a program, custom command or another event's script. The name must match; capitalization is ignored.
@countdown in a script Fires the event when the countdown runs out. See Programs and commands.
"Fires by itself after" Fires after that many minutes of play. Play time counts only while player mode is open, and starts from zero each time player mode starts. In a player file it carries over between visits.
"Also fires" Fires alongside another event. Chains can be any length; each event fires only once, so a chain cannot loop.
Ctrl+Shift+1 to 9 The GM fires event 1 to 9, in list order, during play. Uses the number keys in the top row, not the number pad; on a Mac, hold Control, not Command. The ↑ button moves an event up the list and changes its hotkey.
"Fired" checkbox Fires the event from the GM workspace. Unchecking it reverses this.

Event scripts run one at a time, after whatever is already running. An event fired in the middle of a program speaks once the program has finished. An event with no script fires without any sign on screen; the Events count in the toolbar and the Activity log show which events have fired and how.

Run now

▶ Run now, next to an event's script, plays that script in the terminal straight away, so you can check its timing, sounds and effects without playing up to that point. Nothing in the game changes. Lines that would change it (@trigger, @countdown, @stop, @end, @reveal, @delete) show a dim [TEST] note instead. Questions from @ask wait for your answer as they would for players. Press Enter at the end to return to the Events window. The Commands window has the same button.

Event map

Event map, at the bottom of the Events window, draws the whole scenario as a diagram, in the order things can happen when players play with no GM:

  • Columns are steps. Step 1 events can fire from the start; a step 2 event needs something a step 1 event released or fired, and so on. A last column, Never fires without a GM, holds events nothing can reach.
  • Boxes are events. Each lists what fires it, its hotkey, and tags for what it does: files and mail it releases, a question, a countdown, sound, and ends the game. Endings have a heavy border. A way that can never happen is shown in red.
  • Arrows show what leads to what: one event firing another (@trigger, a countdown, "Also fires"), or releasing the file, program or mail that fires it. A dashed arrow means "Only after".
  • Events with arrows and endings are listed first in each column; side events that lead nowhere sit underneath.
  • Click a box to jump to that event in the Events window.

Text version shows the same map as an outline, including the important lines of each script and its @ask branches, ready to copy or save. Passwords count as solvable in the map; to check that each password has a clue, see the Clue check at the end of the answer key.

Deleting an event

If files or mail are attached, a confirmation appears first. The attached items change to "Always there".

Scenarios from older versions that used numbered rounds are converted automatically into events named Round 1, Round 2 and so on. Each round event also fires the ones before it, so they behave as the rounds did. They can be renamed freely.

6. Programs and custom commands

Programs (.EXE files) and custom commands are short scripts that run line by line. Typical uses include fake hacking tools and decryption sequences.

Script syntax

Each plain line prints to the screen in turn. Lines that begin with @ are instructions:

InstructionEffect
@wait 800Pauses for the given number of milliseconds (1000 = one second). With no number, the pause is half a second.
@progress LabelDraws a progress bar that fills from 0 to 100%, e.g. DECRYPTING [##########..........] 50%.
@clearClears the screen.
@slow TextTypes the text out letter by letter, in a slightly brighter color. Good for a character talking to the players.
@speak TextLike @slow, but the browser also reads the text aloud in a flat, robotic voice. The script continues once the voice has finished.
@sound alarmPlays a sound effect (see Sounds). The script continues once the sound has finished, unless an effect on the next line plays alongside it (see below).
@flashFlashes the screen white. @flash red or @flash #00ff00 flashes another color.
@shakeShakes the screen for half a second. @shake 1500 shakes for 1.5 seconds.
@glitchDistorts the screen and scrambles the last few lines for 0.7 seconds, then puts them back. @glitch 2000 lasts 2 seconds.
@theme Red alertSwitches the terminal to another theme, by name, for the rest of the game. @theme default switches back. See Themes.
@play FOLDER\FILE.GIFPlays an animated GIF once. @play CAMERA.GIF 3 plays it three times. A still picture is simply shown.
@notify MessageSends the message to your Discord channel, so you hear when players reach a point in the game, even from a player file you sent out. See GM notifications.
@ask Question?Waits for the players to type an answer. See Questions and answers.
@countdown 60 Event name | LABELStarts a bar above the prompt that fills over 60 seconds while players keep typing. When it reaches 100%, the named event fires. The label after | is optional.
@stopStops a running countdown, marking it HALTED.
@endEnds the game. Only RESTART works afterwards in a player file; in GM mode, only GMMODE.
@trigger Event nameFires an event. See Events.
@reveal FOLDER\FILEMakes a file visible even if it is hidden or its event has not fired.
@delete FOLDER\FILERemoves a file or folder from the players' computer. The GM workspace keeps it, marked Destroyed.

Paths for @reveal, @delete and @play start at the top of the drive and include the file extension: SECURITY\INCIDENT.LOG. C:\ at the front is optional.

Sound and screen-effect lines (@sound, @flash, @shake, @glitch) placed directly one after another happen at the same time, and the script continues once the longest has finished. A single one on its own line finishes before the next line runs. For a siren while the screen shakes: 

@sound alarm
@shake 1800
MISSILE LAUNCH DETECTED.

Questions and answers

@ask puts its question on the prompt line and waits for the players to type an answer. @if lists the answer to watch for; its lines run only if the players gave it. Lines after @else run for any other answer. @endif closes the branch. 

@slow i can open the vault for you.
@ask TRUST ME? (Y/N)
@if YES, Y
@slow good. you won't regret this.
@trigger Vault opened
@else
@slow then you'll stay here. with me.
@sound alarm
@endif
  • Capitals and extra spaces in the answer are ignored. List several accepted answers with commas: @if YES, Y, SURE.
  • @else is optional. Without it, any other answer simply skips the @if lines.
  • A branch can contain another @ask with its own @if … @endif.
  • Each answer is written to the Activity log.

GM notifications

@notify sends a short message to a Discord channel of yours. It's most useful with player files: you send a game to remote players and get a ping when they reach the vault or an ending.

  1. In Discord, open the channel's settings: Integrations → Webhooks → New Webhook, then Copy Webhook URL. Webhooks need a server, but a private server with only you in it works.
  2. In the kit, open Settings, paste the link into GM notifications and click Send test message.
  3. Add lines such as @notify Someone opened the vault to any script. {answer} inserts the last @ask answer, e.g. @ask YOUR NAME? then @notify {answer} reached the vault.
  • Messages are free and there is no monthly limit. Discord limits only the speed, far above what a game sends.
  • Offline, a message waits and is sent when the player is back online, marked with the time it happened.
  • In your own player mode, messages are marked "(GM test)". Run now only shows a [TEST] note.
  • Player files that use @notify tell players, when they start, that the game sends progress updates to its creator.
  • The link goes into player files but is left out of Export, so a scenario file you share never carries it. Someone digging through a player file's code could still find it; if it is ever misused, delete the webhook in Discord and make a new one.

Sounds

Sounds are made by the browser as it plays, so a scenario carries no audio files and works offline. Browsers only allow sound after the first key press, which means the boot screen is always silent. Players can type SOUND OFF to mute sounds and the @speak voice.

Run now plays a misspelled sound name as a [TEST] note, so typos are easy to catch.

Example

Script for OVERRIDE.EXE:

CONNECTING TO MAINFRAME...
@wait 1200
@progress BYPASSING FIREWALL
SECURITY OVERRIDE ACCEPTED.
@trigger Doors unlocked
@delete SECURITY\CAMERA.LOG

Running it prints the first line and pauses for 1.2 seconds. It then shows a progress bar and the success line, fires Doors unlocked, and deletes SECURITY\CAMERA.LOG.

Running programs

Players type RUN OVERRIDE, or the program name on its own (OVERRIDE or OVERRIDE.EXE). Passwords, user restrictions and self-destruct apply to programs in the same way as to files.

Custom commands

Commands adds words that players can type from any folder, such as PANIC or XYZZY. Each command runs a script in the same format as a program.

  • Commands with "In HELP" checked are listed by HELP. Unchecked commands stay secret.
  • A custom command with the same name as a built-in one, e.g. DATE, replaces it.
  • Text typed after the command name is ignored.
  • ▶ Run now plays the command's script straight away, as for events (see Run now).

7. Running a game

  1. Export the scenario as a backup (see Saving).
  2. Choose the starting account in the "Start as" menu, usually the guest account.
  3. Click Player mode. The boot text plays, then the prompt appears.

Players type commands and press Enter. Clicking the screen returns focus to the command line, and the up and down arrow keys recall earlier commands.

During play

  • Ctrl+Shift+1 to 9 fires events.
  • Typing GMMODE or pressing Ctrl+Shift+G returns to the GM workspace. Starting player mode again restarts the terminal: players are logged out, unlocked passwords are forgotten and the screen clears. To change things mid-game without a restart, use events.
  • A GM passphrase, set in Settings, stops players leaving player mode. GMMODE then asks for it, and a wrong entry shows the normal "Bad command or file name". Unlike other passwords, the passphrase is case-sensitive.

Activity log and answer key

Activity shows a timestamped list of player commands, files read, programs run, wrong password guesses and fired events. It keeps the latest 400 entries.

Answer key lists accounts, passwords, restricted and hidden files, self-destructing files, programs, and each event with what it unlocks. Copy and Save file… keep a copy. The Clue check section at the end lists passwords that appear in no file, mail or script. Players can only learn those from a handout or from the GM.

9. Between sessions: Reset session

Changes made during a game stay in the scenario afterwards, including self-destructed files and fired events. Reset session returns the scenario to its starting state and first lists what it will change:

  • Restores destroyed and deleted files.
  • Undoes program reveals.
  • Turns fired events off (this option can be unchecked).
  • Optionally clears the Activity log.

Files, accounts, mail, commands and settings are not affected. To restore a single file instead, open its Get Info and uncheck "Destroyed during play" or "Revealed by a program".

New blank scenario and Load sample in Settings replace the current scenario, so export it first.

11. Saving, Export and Import

The kit saves automatically to the browser it is running in. Nothing is sent over the internet. As a result:

  • Each browser keeps a separate copy. A scenario built in Chrome does not appear in Safari.
  • Clearing the browser's history or site data can erase it.
  • Private and incognito windows discard it when they close.

Export saves the scenario as a .json file, which can be kept as a backup or moved to another computer. Import loads a .json file and replaces the open scenario. Exports do not include the Activity log.

Export before each game. The export file is the only backup.

Storage warning

Browsers allow each page a few megabytes of storage, and large images fill it fastest. When a save fails, a red banner appears below the toolbar.

The scenario is still complete in the open page. Export now in the banner saves a copy. Deleting or replacing large images frees space, and smaller, simpler images also convert to clearer ASCII art. The banner disappears once saving works again. Closing or reloading the page before exporting loses any unsaved changes.

12. Player files

Export for players saves a separate HTML file for players to work through on their own, without a GM. The file opens straight into the terminal and has no GM workspace.

Before exporting

Test the whole scenario in player mode first. The export window then checks for two problems:

  • Events nothing can fire. Without a GM, an event only fires from @trigger in a program or command, from a timer, or from another event's "Also fires". The window lists each such event and what it would unlock.
  • Passwords with no clue. These are passwords that appear in no file, mail or script, so players can only learn them if they are sent separately.

Either can be fixed in the scenario, or ignored with Export anyway, for example when the passwords go out with the file. "Players start as" sets the account players begin with.

What the file contains

  • The scenario in its starting state. Fired events, destroyed files and reveals from test runs are left out, and so are the GM passphrase and the Activity log.
  • Files and folders with a password are encrypted with that password. Their contents cannot be read from the file without it. Account passwords are stored only in a one-way scrambled form.
  • Everything else (hidden files, files waiting for an event, mail and commands) is scrambled. It cannot be read in a text editor, but someone who can read code could decode it.

For players

  • Progress saves automatically in the player's browser: location, login, unlocked passwords, fired events and destroyed files. Opening the file again continues the game.
  • RESTART, confirmed with RESTART YES, starts the game over. After an ending, RESTART alone does it, and reopening the file also starts fresh.
  • A running countdown is saved too, so reloading the page does not escape it.
  • GMMODE and the GM hotkeys do nothing.
  • Each export is a new file. Progress made in an earlier export does not carry over.

The file needs to be opened directly from the computer, or from a web address starting with https://. Other web addresses block the encryption, and passwords cannot be checked.

13. Recipes

Puzzle chain

A password leads to a program, which releases the next clue.

  1. Create the event Vault opened.
  2. Set VAULT.TXT to appear when Vault opened fires.
  3. Give CRACK.EXE a password, and put that password in another file.
  4. End the CRACK.EXE script with @trigger Vault opened.

Mail on cue

A message arrives at a moment the GM chooses.

  1. Create the event The call with the announcement *** 1 NEW MESSAGE ***.
  2. Add a message to the right account and set its "Arrives when" menu to The call.
  3. Move the event to the top of the list, so its hotkey is Ctrl+Shift+1.
  4. Press the hotkey at that point in the story.

Race against the clock

A finale where players must type a code before a countdown runs out.

  1. Create the event Too late, with a script describing the bad ending and ending with @end.
  2. Create the event Saved with the condition "Types SHUTDOWN 4471" and a script that starts with @stop, describes the good ending and ends with @end.
  3. In the program or event that starts the finale, add @countdown 60 Too late | REACTOR CRITICAL.
  4. Optional: a custom command SHUTDOWN that prints CODE REJECTED answers wrong codes.

Burn after reading

In a text file's Get Info, check "Self-destructs after it is read or run". The file can be read once, after which it is gone for players.

Erasing evidence

A custom command, WIPE, that deletes a log and alerts security:

@progress ERASING LOGS
@delete SECURITY\ACCESS.LOG
LOGS ERASED.
@trigger Security alerted

Hidden bonus clue

Set a file to "Hidden from DIR". Players who use DIR /A, or who guess the file name, can find it.

Two groups, one computer

Give each group its own account, with private files ("Only this user can open it") and separate mail. "Start as" sets which group begins, and LOGIN switches between them.

14. Troubleshooting

Scenario missing
Check that the browser is the one the scenario was built in, and not a private window. If the browser's data was cleared, Import the most recent export.
File not visible to players
Check the Get Info of the file and of each folder above it. Possible causes are an event that has not fired, "Hidden from DIR" (DIR /A lists it), a restriction to another account, or Destroyed status. The file's badges show each of these.
Hotkey has no effect
Hotkeys only work in player mode, only for the first nine events, and only once per event. They use the top-row number keys, with Control (not Command) on a Mac. An event with no announcement fires silently; the Events count shows whether it fired.
@reveal, @delete, @play or @trigger has no effect
For @reveal, @delete and @play, give the full path from the top of the drive, with the extension: SECURITY\INCIDENT.LOG. For @trigger, the event name must match the one in the Events window; capitalization is ignored. In all of them, the @ must be the first character on the line. Run now shows what a script does, line by line.
A custom command stopped responding
An event's "Types" phrase starting with the same word takes priority while that event is waiting to fire. The custom command answers again once the event has fired, or for any other text typed after the command name.
FIND misses a file
FIND skips hidden and password-protected files by design, so it cannot be used to bypass puzzles.
Cannot leave player mode
Type GMMODE and enter the passphrase exactly, including capitals. Reloading the page also works: it always opens in the GM workspace, and the scenario is kept.
Terminal font looks different
The terminal fonts load from Google Fonts. Without an internet connection the kit uses a font already on the computer instead, and everything else works the same.
No sound or voice
Check that the computer isn't muted and that players haven't typed SOUND OFF (SOUND ON turns it back on). Sounds only start after the first key press. The @speak voice depends on the voices installed on the computer, so it sounds different on Mac, Windows and phones; where no voice is available, the text is still typed out.
Player file says passwords cannot be checked
The file was opened from a web address that does not start with https://. Download it and open it directly from the computer instead.
Restricted files no longer open
The account they are restricted to was probably renamed. Update the files' Get Info to the new name.
